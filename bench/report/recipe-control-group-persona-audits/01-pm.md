## Persona

Experienced PM / EM running a **repo-agnostic** feature: PRD in hand, Jira epic + phase tasks for visibility, milestone comments for stakeholders, need to know status when execution stalls, and **settle only after PO sign-off + CI green**. Comfortable with Cursor Agent invoke-by-name skills, not writing bash. Expects one onboarding path and one “where are we?” path.

---

## Happy path (commands they would run, in order)

1. **`recipe-install`** — stage full recipe into target repo (or `./.gsd-recipe/scripts/install.sh --yes` from benchmark checkout).
2. **`recipe-validate-tokens`** — optional sanity check on `gh` + Atlassian MCP before Jira work.
3. **`recipe-onboard docs/PRD.md --project <KEY>`** — single chain: PRD → `.planning/*` → Jira Epic → phase sub-tasks (skips steps whose artifacts already exist).
4. **`recipe-bootstrap-knowledge`** — scaffold `.knowledge/` + map/graphify/ingest.
5. **`recipe-plan-phase 1`** → **`recipe-run-phase 1`** — plan + execute with soft policy gate; Jira `plan_complete` / `execute_*` synced by wrappers.
6. Repeat step 5 per phase, or **`recipe-run-phases [<start> <end>]`** for sequential loop.
7. **`recipe-verify-feature N`** → **`recipe-review-ship N`** → **`recipe-settle N`** — UAT (conversational) → code review + PR → CI check then live PO y/n → epic `settled` comment.
8. **`recipe-sync`** — one-shot detect→queue→drain if milestone comments were missed or MCP failed mid-run.
9. **`recipe-pr-comment <event_id> <pr#> --phase N`** — optional GitHub PR milestone comments (separate from Jira).
10. When stuck on “what’s next” today: **`gsd-progress`** (native GSD, not recipe) + inspect `.planning/STATE.md`, `.planning/phases/*/PLAN.md|SUMMARY.md`, Jira epic/tasks.

## Friction / problems

- **P0 — No situational “stuck” command.** `recipe-help` explicitly forbids unsolicited next-step suggestions (`recipe-help-SKILL.md` § C.3, § D); TASK-038 (`recipe-help --next` / `--stuck`) is **planned**, not built (`BACKLOG.md` Wave 5, `DECISIONS.md` OD-11). PM mid-flight gets a catalog, not a recommendation.
- **P1 — Status split across two worlds.** Recipe traceability lives in `.planning/STATE.md`, sync ledger/queue, Jira; execution progress lives in native **`gsd-progress`** (`RECIPE-COMMANDS.md`). No single recipe-native PM status view.
- **P1 — Milestone comments are not automatic.** `recipe-sync` is one-shot; recurrence is operator’s job or external `/loop` (`recipe-sync-SKILL.md`, OD-05). Wrappers sync on invoke, but ad-hoc native GSD calls or MCP failures leave Jira stale until someone runs sync.
- **P1 — Stacked confirm gates.** `recipe-onboard` adds a preview gate, then each chained skill adds its own (`recipe-create-epic` project picker + create confirm; `recipe-create-phase-tasks` batch confirm). Documented as intentional but heavy for a PM who thought “one onboard” meant one approval.
- **P1 — `discuss_complete` has no recipe wrapper.** Deferred in `recipe-onboard-SKILL.md`; only native **`gsd-discuss-phase N`** + manual **`gsd-jira-sync discuss_complete`** posts to epic (`README.md` event table). Easy to skip phase-level discuss traceability.
- **P1 — Phase-task creation ≠ milestone visibility.** `recipe-create-phase-tasks` creates/links issues only; explicitly does not post comments (`recipe-create-phase-tasks-SKILL.md` § D). PM may expect Jira tasks to show activity immediately.
- **P1 — `--full` multi-phase loop + epic-level `settled`.** `recipe-run-phases --full` calls **`recipe-settle N` per phase** (`recipe-run-phases-SKILL.md` § 4.d), but `settled` routes to **epic**, not phase task (`recipe-settle-SKILL.md`, `TRACEABILITY-LLD.md`). Semantically wrong for multi-phase epics; ledger may dedupe, PO still prompted repeatedly.
- **P2 — `recipe-new-project` status inconsistent.** README marks TASK-036 **Planned**; template + installer exist; `RECIPE-ONBOARD.md` references `install-recipe-new-project.sh`. PM cannot tell if bootstrap wrapper is “real” or fallback-only.
- **P2 — Settle blocked on GitHub-shaped CI.** `recipe-settle` requires `gh`, GitHub remote, PR/check-runs (`recipe-settle-SKILL.md` § B–C). Non-GitHub or pre-PR work needs manual `--owner-repo`/`--ref` with no PM-oriented doc.
- **P2 — CI `WARN` = blocked settle.** Inconclusive check-runs treated like failure (`recipe-settle-SKILL.md` § C.3). Conservative for quality floor; frustrating when checks are flaky or missing.
- **P2 — Failed sync rows can stick.** Drain mode: skipping `mark-failed` leaves queue rows stuck (`gsd-jira-sync-SKILL.md`). PM sees missing Jira updates with no runbook unless they read failure matrix.
- **P2 — DAG / phase dependencies not enforced.** TASK-009 parked; `depends_on` is reminder-only (`recipe-plan-phase-SKILL.md`). PM cannot rely on recipe to block out-of-order phase execution.

## Missing guidance for PMs

- **When to run `recipe-sync` vs trusting wrappers** — no cadence doc (after each phase? daily? only on failure?).
- **Epic vs phase-task comment routing** — table exists in `README.md` / `TRACEABILITY-LLD.md` but not in PM-facing `RECIPE-ONBOARD.md` or `recipe-help` default tour.
- **`gsd-progress` vs recipe artifacts** — what each answers; no mapping (“phase 2 executing” vs “Jira comment not posted”).
- **PO role boundaries** — `gsd-verify-work` (phase UAT) vs `recipe-settle` (epic acceptance + CI) both need human input; README says verify ≠ settled but not in onboarding quick start.
- **Mid-flight recovery playbook** — read `STATE.md`, check `sync-queue.jsonl`, re-run failed skill, drain sync; scattered across LLDs, not one PM page.
- **Pre-seeding Jira flags** — `--project`, `--issue-type`, `--transition "Done"` documented per skill but not in a “PM runbook” for repeatability across teams.
- **GitHub PR comments** — `recipe-pr-comment` exists; OD-09 cadence still open; PM not told when PR comments matter vs Jira-only v1.

## False assumptions or traps

- **`recipe-onboard` ≠ fully installed recipe** — still need `recipe-install` + MCP auth first (`RECIPE-ONBOARD.md` Prerequisites).
- **`recipe-help` will tell me what to run next** — it will not (`recipe-help-SKILL.md` § C.3).
- **Onboarding one confirm = one human decision** — nested gates still fire inside epic/phase-task skills.
- **Jira tasks created = project kicked off in tracker** — only `intake_started` (epic) and phase wrappers emit milestones; new phase tasks are silent until plan/run.
- **`gsd-verify-work` acceptance = feature settled** — locked rule: settled = PO + CI only (`README.md` Locked rules, `recipe-settle-SKILL.md`).
- **`recipe-run-phases --full` settles the epic per phase** — epic-level event invoked with phase number as label only; misleading for multi-phase delivery.
- **Milestone sync is continuous** — reconcile detects; posting requires explicit drain (`recipe-sync` / wrapper invoke).
- **Settle can be scripted/non-interactive** — no `--yes` on PO gate by design (`recipe-settle-SKILL.md` § D).
- **PRD intake replaces phase discuss** — `recipe-onboard` explicitly deferred `recipe-discuss-phase`; phase discuss still native + manual sync.
- **`.planning/` in git = shared PM view** — locked decision: scaffold gitignored on external targets (`DECISIONS.md`); Jira may be only shared source of truth.

## Suggested recipe improvements (actionable, repo-agnostic)

1. **Ship TASK-038** — `recipe-help --next` + `--stuck <symptom>` from generic artifacts only; keep default catalog unchanged.
2. **Add `recipe-status` (read-only)** — one screen: ROADMAP phase, latest PLAN/SUMMARY presence, tracker keys, ledger queue depth, last synced event — no product paths.
3. **PM one-pager in `RECIPE-ONBOARD.md`** — epic vs phase routing table + “after onboard, run X before planning.”
4. **Document sync cadence** — “after each wrapper skill” + “run `recipe-sync` if Jira stale / MCP error” + link to FAILURE-MATRIX row.
5. **Fix `--full` + settle semantics** — settle once at end of range (or last phase only), not per phase; or rename/document as “phase ship checkpoint” vs epic `settled`.
6. **Resolve TASK-036 catalog drift** — mark `recipe-new-project` built or document “native fallback only” in README + RECIPE-COMMANDS status column.
7. **Optional `recipe-discuss-phase N` wrapper** — thin gate + `discuss_complete` sync for PMs who want phase discuss in Jira without memorizing native command.
8. **Config presets for Jira** — `.gsd-recipe/config.json` keys for default `project`, `issue_type`, settle `transition` to skip live MCP pickers.
9. **Settle CI guidance for edge cases** — when to pass `--ref`, monorepo/multi-PR, non-GitHub (defer with explicit “not v1” message).
10. **Post–phase-task bootstrap comment** — optional epic comment listing created phase keys (not full lifecycle spam) so PM sees kickoff in Jira.
11. **Unify “stuck” entry points** — `recipe-help --stuck no-epic|ci-red|plan-policy-warn|sync-queue-stuck` FAQ strings from TASK-038 spec.
12. **TASK-039 template overrides** — org PRD/Jira comment templates without forking (PM customization without engineering fork).
